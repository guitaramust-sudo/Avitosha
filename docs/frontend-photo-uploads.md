# Фотографии объявлений: памятка для frontend

Frontend больше не просит пользователя вставлять внешние ссылки. Файл загружается напрямую из браузера в наш MinIO, а backend только выпускает короткоживущую подписанную S3-форму. Секретный ключ MinIO никогда не передаётся в браузер.

## Контракт

1. Авторизованный frontend отправляет `POST /api/v1/uploads/listing-photos`:

```json
{
  "fileName": "sofa.jpg",
  "contentType": "image/jpeg",
  "size": 524288
}
```

2. Backend возвращает `201` с `url`, `fields`, `publicUrl`, `objectKey`, `expiresAt` и `maxFileSize`.
3. Создайте `FormData`, добавьте в неё все пары из `fields` без изменений, затем последним полем добавьте `file`.
4. Отправьте `POST` на относительный `url` без заголовка `Authorization` и без ручной установки `Content-Type`. Успешный ответ хранилища — `204`.
5. После успеха добавьте `publicUrl` в `photoUrls` объявления. Сам backend объявления по-прежнему принимает массив URL, поэтому старые фотографии остаются совместимыми.

Готовая реализация находится в `app/frontend/src/api/marketplace.ts` (`uploadListingPhoto`) и используется формой объявления.

## Ограничения и ошибки

- Допустимы `image/jpeg`, `image/png`, `image/webp`.
- Не больше 10 МБ на файл и 10 фотографий на объявление.
- Если подписанная форма истекла или загрузка упала, запросите новую форму; старую повторно сохранять не нужно.
- Не добавляйте `publicUrl` в объявление до успешного ответа Object Storage.

## Как устроен MinIO

`docker compose up --build` запускает MinIO вместе с приложением. Одноразовый `minio-init`:

- создаёт бакет `avitosha-photos`;
- создаёт отдельного пользователя, которому разрешена только запись;
- разрешает анонимное чтение фотографий;
- переносит существующие демо-фотографии в префикс `demo/`.

В development Vite проксирует `/storage/*` в MinIO на порту `9000`. В production тот же путь проксирует Caddy. Поэтому frontend использует одинаковые относительные URL и не зависит от адресов контейнеров или отдельного S3-домена.

MinIO Console локально доступна на `http://localhost:9001`. Учётные данные задаются переменными `MINIO_ROOT_USER` и `MINIO_ROOT_PASSWORD`.

## Production

Перед запуском заполните в `.env.prod` четыре разных длинных значения:

- `MINIO_ROOT_USER` и `MINIO_ROOT_PASSWORD` — только для администрирования MinIO;
- `MINIO_APP_ACCESS_KEY` и `MINIO_APP_SECRET_KEY` — для подписи загрузок приложением.

Файлы находятся в Docker volume `avitosha_prod_minio_data`. Он переживает перезапуск и пересоздание контейнеров, но не потерю диска VM. Этот volume нужно включить в регулярное резервное копирование вместе с PostgreSQL.

Первый запуск скачивает старые демонстрационные изображения из прежнего бакета и сохраняет их в MinIO. После успешного `minio-init` приложение отдаёт их только через `/storage/avitosha-photos/demo/...`; повторный запуск использует локальный seed-volume.

Нельзя публиковать порт `9001` в production. Для аварийного доступа к консоли используйте SSH port forwarding до контейнера или временный закрытый admin-маршрут.
