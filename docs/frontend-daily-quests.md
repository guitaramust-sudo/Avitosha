# Daily quests: памятка для frontend

Данные приходят внутри `GET /api/v1/daily-summary` в поле `retention`. Backend сам создаёт и закрепляет набор на календарный день по Москве (`00:00 Europe/Moscow`), поэтому frontend не должен выбирать, перемешивать или сохранять задания локально.

## Что возвращает API

`retention.dailyGoal` содержит:

- `quests` — ровно 5 заданий: 2 с ролью `BUYER`, 2 с ролью `SELLER`, 1 с ролью `UNIVERSAL`;
- `completed` и `required` — прогресс общей цели (сейчас нужно выполнить любые 2);
- `status` — `ACTIVE`, `REWARDED` или `EXPIRED`;
- `xpReward` — XP за закрытие общей цели;
- `reward` — Avito-бонусы за закрытие общей цели;
- `balancedCompleted` и `balancedReward` — дополнительный бонус за хотя бы одно выполненное задание покупателя и продавца.

Каждый элемент `quests` содержит `role`, `progress`, `target`, `status` и `xpReward`. XP отдельного задания начисляется один раз при его завершении. Оставшиеся задания можно выполнять после закрытия цели 2 из 5.

`retention.tomorrow` намеренно содержит только состав и награды следующего дня (`tasksCount`, `buyerTasks`, `sellerTasks`, `universalTasks`, `required`), но не раскрывает сами задания.

## Важное поведение

- Стрик продлевается не при входе и не при первом действии, а только после закрытия цели 2 из 5.
- Каждые 7 успешных дней backend выдаёт один щит (`streak.protections`); он автоматически сохраняет серию при одном пропущенном дне.
- Набор не меняется при обновлении страницы.
- Счётчики увеличивает только backend после засчитанного продуктового действия.
- Повтор одного `eventId` не начисляет XP или бонусы второй раз.
- Одно действие продвигает максимум одно задание из каждой роли; backend не выдаёт в дневном наборе два задания одной роли с одинаковым `actionType`.

## Realtime

После действия могут прийти события:

- `DAILY_QUEST_UPDATED` — обновить дневную сводку;
- `DAILY_QUEST_COMPLETED` — показать завершение задания и `xpReward`;
- `DAILY_GOAL_COMPLETED` — показать основную награду дня;
- `BALANCED_DAY_COMPLETED` — показать бонус за обе роли;
- `STREAK_UPDATED` — обновить серию;
- `XP_EARNED` и `AVITO_REWARD_EARNED` — обновить питомца, лидерборд и кошелёк.

Самый надёжный frontend-сценарий после этих событий — инвалидировать запросы дневной сводки, питомца и кошелька, а не рассчитывать итоговые балансы на клиенте.

Актуальные TypeScript-типы находятся в `app/frontend/src/types/game.ts`, формальный HTTP-контракт — в `app/backend/api/openapi.yaml`.
